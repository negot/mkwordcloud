# 可観測性設計

対象: デプロイスクリプトの実行記録。アプリ本体の監視の追加は対象外で、既存のダッシュボードとアラームは変更しない。

## 記録の三層

| 層 | 保管先 | 内容 | 要件 |
|---|---|---|---|
| 標準出力 | 画面(保存しない) | ステップごとの開始、終了、結果、所要時間(StepTimer)。差分、警告、失敗の詳細 | NFR3.1 |
| 承認ログ | git 管理外のファイル(JSON Lines) | 試行ごとの `abort`、`start`、`approval` などの行 | NFR1.4、NFR1.5 |
| CloudFormation のイベント | AWS 上 | スタックの変更履歴。失敗時に FailureReporter が取得して表示する | NFR5.7 |

## 承認ログの構造

試行ごとに、同じ `attemptId` を持つ複数の行を追記する。

| 行の種類 | 主な項目 |
|---|---|
| `abort` | 承認の前に中止したときだけ書く。日時、実行ユーザー、コミット(取得できたとき)、中止した段階(事前確認、ビルドと検証、再確認、ログの書き込み)、理由。テンプレートのハッシュ、アカウントの情報など、その時点で存在しない項目は省く |
| `start` | テンプレートの生成と差分の後、承認プロンプトの前に書く。日時、実行ユーザー、STS のアカウント ID と ARN、コミット、保存先のハッシュ(承認時のハッシュ)、リージョン、変更の要約、データ消失の警告の有無。承認の結果は含まない |
| `approval` | 承認プロンプトとハッシュの再照合の後、デプロイの前に書く。日時、データ消失の警告への回答、承認の判断(承認、拒否)、ハッシュの再照合の結果(承認時のハッシュ、現在のハッシュ、一致か不一致か)。承認の判断をデプロイ前に記録する行である。書けないときはデプロイしない |
| `deploy` | 日時、結果、スタックの状態、失敗したリソースと理由、CDK の確認で拒否されたかどうか |
| `postcheck` | 日時、自動確認の項目と結果、再試行の回数 |
| `humancheck` | 日時、回答者、項目ごとの結果(確認した、確認しなかった、問題があった)。確認しなかった項目は「未確認」 |
| `end` | 日時、終了コード、所要時間の合計 |

- 記録の規則は、`logical-components.md` の「実行の流れ」による。要点は次のとおり。
  - `start` 行を書く前に中止した試行は、`abort` 行だけを記録する(`start` と `end` は書かない)。
  - `start` 行を書いた後に止まった試行(承認の拒否、データ消失の確認の拒否、ハッシュの不一致)は、`approval` 行と `end` 行を記録する。
  - 承認ログ自体に書けないときは、理由を画面に表示して非ゼロで終了する。画面の表示が唯一の記録になる。
- NFR1.4 の「試行ごとに 1 行」は、「試行ごとに、同じ `attemptId` を持つ行の組を記録する」と読み替える。1 行にまとめると、デプロイ前に承認の判断を記録するため(`approval` 行)と、フェイルクローズの要件(承認の証拠が書けなければデプロイしない)を満たせないためである。この読み替えは、設計が NFR1.4 の文言を緩めるものとする。
- 書き込みは、1 行を 1 回の追記で行う。書けないときの扱いは、`security-design.md` による。

## 人による確認の記録(NFR1.5)

人による確認は、三つの項目を 1 件ずつ尋ねる。

1. 画面表示
2. WebSocket の接続
3. 送信から表示までの動作

回答は「確認した」「確認しなかった」「問題があった」のいずれかで、`humancheck` の行に残す。「確認しなかった」は未確認として記録し、失敗とはしない。「問題があった」が一つでもあれば、非ゼロで終了する。

## 指標(SLI)と目安(SLO)

目標として強制せず、記録のために出す。

| 指標 | 出す場所 | 目安 |
|---|---|---|
| 所要時間の合計とステップごとの時間 | 標準出力と `end` の行 | 15 分(Q5 C。超えても失敗としない) |
| 自動確認の再試行の回数 | `postcheck` の行 | 記録のみ |
| 事前確認の失敗の項目 | `start` の行と標準出力 | 記録のみ |

## 既存の監視

既存の CloudWatch のダッシュボードとアラームは変更しない。差分に含まれるときは、承認プロンプトの前に表示して、人が気づけるようにする。アラームの通知先の追加は行わない。

## 相関

1 回の実行を `attemptId`(日時とコミットのハッシュから作る)で束ね、標準出力と承認ログのすべての行に付ける。
