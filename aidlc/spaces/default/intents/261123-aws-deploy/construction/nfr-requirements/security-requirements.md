# セキュリティ要件

対象: 承認つきデプロイスクリプトと、そこで使う AWS の認証と権限。

## 認証と認可

| ID | 要件 | 出典 |
|---|---|---|
| NFR2.1 | AWS への認証は、長期のアクセスキーを使わない一時的な認証(IAM Identity Center)とする。IAM ユーザーのアクセスキーは使わない | 要件定義 FR4.1、NFR2 |
| NFR2.2 | デプロイに使う権限は、IAM Identity Center の管理者権限(AdministratorAccess)とし、権限は絞らない。そのため、管理者権限が使えるのは本番デプロイの承認プロンプト(FR3.2)を通った後だけとし、スクリプトは承認前に AWS を変更する操作を実行しない(読み取りと差分の取得は除く)。この方針で残る権限の広さのリスクは、受け入れる | [Q4] |
| NFR2.3 | スクリプトは、AWS の認証情報(アクセスキー、セッショントークン、SSO のトークン)を、ファイル、標準出力、ログ、承認ログに書き出さない | 要件定義 FR4.2 |

## データ保護と記録

| ID | 要件 | 出典 |
|---|---|---|
| NFR2.4 | 承認ログは、リポジトリ内の git 管理外のファイルに残す。ファイルは `.gitignore` に登録し、git に追加されないことをテストで確認する。保管期間は決めない | [Q5]、FR3.5 |
| NFR2.5 | 承認ログには、日時、承認者(実行ユーザー名)、コミットのハッシュ、アカウントとリージョン、変更の要約、結果だけを書く。秘密情報、トークン、入力されたテキストは書かない | FR3.5、NFR2 |
| NFR2.6 | 入力テキストを保存もログ出力もしない既存の方針を変えない。デプロイ後の確認でも、テストデータを送信しない | 要件定義 FR5.2、architecture.md |
| NFR1.1 | 本番デプロイは、確認プロンプトで承認されない限り実行されない。`--require-approval never` を使わない | [Q6 要件定義]、project.md の Mandated |

## 脅威への考慮

| 脅威 | 対策 |
|---|---|
| 認証情報の漏えい | NFR2.1、NFR2.3。長期の鍵を持たず、出力に書かない |
| 承認なしの変更 | NFR1.1。承認の前に変更系の操作を実行しない(NFR2.2) |
| 誤ったアカウントやリージョンへのデプロイ | FR3.7 の事前確認で、アカウントとリージョンを表示して一致を確認する |
| データ消失を伴う変更 | FR3.6。警告と、別の確認プロンプトを経た場合に限り先に進む |
| 承認ログの改ざん | 対策しない。単独の開発者が使う手元ファイルで、改ざんの防止は目標に含めない。[assumption] |
