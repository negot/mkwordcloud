# 可観測性要件

対象: デプロイスクリプトの実行記録と、デプロイ後の状態の確認。アプリ本体の監視の追加は、今回の対象外(要件定義の Out of Scope)。

## ログと記録

| ID | 要件 | 出典 |
|---|---|---|
| NFR3.1 | 同じコミットから同じ手順でデプロイでき、各ステップの開始、終了、結果を標準出力に表示する | 要件定義 NFR3 |
| NFR1.4 | 承認ログに、デプロイの試行ごとに 1 行を追記する。項目は、日時(UTC)、承認者、コミットのハッシュ、アカウントとリージョン、変更の要約、結果とする。停止した試行と、DynamoDB や S3 の警告への回答(FR3.6)も記録する | FR3.5、FR3.6 |
| NFR1.5 | デプロイ後の人による確認(画面表示、WebSocket の接続、送信から表示までの動作)について、確認した、確認しなかった、問題があった、のいずれかを 1 項目ずつ承認ログに記録する | FR5.5 |
| NFR5.7 | 失敗時は、`WordcloudStack` の状態、失敗したリソースとその理由を表示する | FR6.2 |

## 保管

- 承認ログは git 管理外のファイルに残し、保管期間は決めない。[Q5]

## 現行の監視(変更しない)

- 既存のスタックにある CloudWatch のダッシュボードとアラームは、変更しない。差分(FR3.2)に含まれる場合は、承認の前に表示する。(infra/test/stack.test.ts が検証する既存の構成)
- アラームの通知先の追加や、新しい監視の追加は行わない。

## SLI と SLO

デプロイスクリプトの実行について、次の指標を目安として記録する。目標値として強制はしない。

| 指標 | 目安 |
|---|---|
| 所要時間 | 15 分以内(NFR3.4) |
| 事前確認の失敗率 | 記録のみ。目標なし |
