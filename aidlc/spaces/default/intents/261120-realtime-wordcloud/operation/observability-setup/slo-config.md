# SLO / SLI

決定: SLO は文書に記録するだけとし、専用のアラームやエラーバジェットの管理は行わない。[Q3]

## 対象期間

- 各ワークショップの開催中(数時間)。常時運用のサービスではないため、30日間などの長期の目標は置かない。

## SLI と SLO

| SLI | 定義 | SLO | 根拠 | 確認方法 |
|-----|------|-----|------|----------|
| 送信の成功率 | 参加者の送信のうち、`ack` が返った割合(利用者の操作による拒否 `too_long`、`too_fast`、`too_many`、`empty` は分母から除く) | 開催中に 99% 以上 | 要件 NFR1.3(取りこぼしが無いこと) | ダッシュボードの Lambda エラー数と WebSocket エラー。開催後は `log-queries.md` |
| 反映の遅延 | 送信から、表示ページへ `update` が届くまでの時間 | 開催中の 95% が 3秒以内 | 要件 NFR1.2 | 事前の負荷試験(`npm run load-test`)。当日はダッシュボードの `WsHandler` 実行時間 p95 を目安にする |
| 表示ページの可用性 | `WebUrl` が HTTP 200 を返すこと | 開催中に常に応答する | 要件(プロジェクター投影) | 開始前のスモークテスト |

## 運用上の目安

- `WsHandler` の実行時間 p95 は、反映の遅延の大部分を占める。p95 が 2秒を超える状態が続く場合は、3秒の目標を超える恐れがある(当日は、主催者がダッシュボードで確認する)。
- 日本語を含む最初の送信は、辞書の読み込み(コールドスタート)で約3.1秒かかった。開始の数分前に、ダミーのルームで日本語を1回送信して温める。

## AWS 上の負荷試験の結果(東京 `ap-northeast-1`)

担当者が `npm run load-test` を実行し、その出力を共有した。

| 項目 | 結果 |
|------|------|
| 条件 | 参加者 100 クライアント、表示側 1、30秒間、各クライアント 3,500ms 間隔で送信(ルーム `9TXWH43V`) |
| 接続 | 参加者 100/100(失敗 0)、表示側 1 |
| 送信 | 864件、ack 864件、表示側が受けた反映 864件(update 864通) |
| エラー | 0件(レート制限・スロットリングなし) |
| 取りこぼし | 0件 |
| 反映の遅延 | p50 85ms、p95 129ms、最大 188ms |

- 送信の成功率: 100%(SLO 99% 以上を満たす)。
- 反映の遅延: p95 129ms(SLO 3秒以内を満たす)。
- 判定: 要件 NFR1.2(反映3秒以内)と NFR1.3(取りこぼしなし)は、AWS 上で合格。
- 注記: 試験の時点で Lambda は温まっていた。日本語を含む最初の送信のコールドスタート(約3.1秒)は、この結果に含まれない。
