# ヘルスチェック報告(東京 `ap-northeast-1`)

## 確認できたこと(外部から、実際のデプロイ先に対して)

| 対象 | 確認 | 結果 |
|------|------|------|
| CloudFront(表示ページ) | HTTP 200、HTTPS への転送、セキュリティヘッダー、`config.json` | 正常 |
| HTTP API(Lambda) | ルームの作成・確認・リセット・終了、CORS、Origin の拒否 | 正常 |
| WebSocket API(Lambda) | 接続、同期、送信、配信、レート制限、文字数制限 | 正常 |
| DynamoDB | ルームの作成、集計、リセット、削除 | 正常(Lambda 経由で確認) |

## 確認できていないこと

- CloudWatch の指標とアラーム。AWS の認証情報がこのシェルに無いため、担当者がコンソールで確認する。
- 100人規模の負荷の下での挙動。デプロイ後の負荷試験(`npm run load-test -- --api <ApiUrl> --ws <WsUrl> --clients 100 --duration 30`)は未実施。
- コールドスタート。日本語を含む最初の送信は約3.1秒かかった。ワークショップの数分前に、ダミーのルームで日本語を1回送信して Lambda を温める。

## 判定

- 外形のヘルスチェックは正常。CloudWatch の確認、100人規模の負荷試験、実際のブラウザでの確認は、担当者の作業として残っている。
