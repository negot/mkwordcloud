# 要件分析 質問票

ご依頼の内容(Chrome拡張 → サーバー → ワードクラウド表示、約100人、AWSデプロイ、IaC)は明確なため、設計・スタックで選択肢のある点だけを質問します。各質問の先頭の選択肢が推奨案です。

## Q1. [アーキテクト] AWS上の全体構成はどれにしますか?

運用負荷とコストに直結する最大の判断です。約100人・数秒に1回の入力は、1秒あたり数十リクエスト程度で、小さな構成で十分です。

- A. サーバーレス構成(推奨): CloudFront + S3(表示ページ) / API Gateway WebSocket API + Lambda(送信・配信) / DynamoDB(集計)。使った分だけの課金で、ワークショップ当日以外はほぼ0円。サーバー管理・パッチ当てが不要で、AWS管理のHTTPS/WSSがそのまま使える。
- B. ECS Fargate 1コンテナ + ALB(Node.js + Socket.IOなど): 実装は素直だが、起動している間は常時課金(ALBだけで月約2,000円〜)。コンテナ運用が必要。
- C. App Runner 1サービス: 構成は簡単だが、WebSocketの扱いとコスト面で制約がある。
- D. EC2 1台: 最安にもできるが、OS管理・証明書・可用性をすべて自分で面倒を見る必要がある。
- X. Other (please specify)

[Answer]:A

## Q2. [開発者] 実装言語と、日本語の形態素解析の方法はどれにしますか?

日本語は単語に分割し、助詞などを除外する必要があります。Lambda上で動かすため、辞書の同梱方法が論点です。

- A. TypeScript(Node.js)で統一 + kuromoji.js(推奨): 拡張機能・サーバー・CDKを同じ言語で書ける。辞書をLambdaに同梱でき、品詞情報で助詞・助動詞・記号を除外できる。コールドスタート時に辞書読み込みで1〜2秒かかる点は許容する。
- B. サーバーのみPython(Janome / SudachiPy)、他はTypeScript: 辞書品質は高いが、言語が2つになりビルド・デプロイが複雑になる。
- C. 形態素解析をブラウザ側(Chrome拡張)で行い、分割済みの語だけを送る: サーバーは軽くなるが、拡張機能のサイズが大きくなり、クライアントを信用する形になる。

[Answer]:A

## Q3. [開発者] ワードクラウドの描画ライブラリはどれにしますか?

- A. d3-cloud(+ d3、SVG描画)(推奨): 頻度に応じた文字サイズ・配置が安定しており、プロジェクター投影向けに大きく表示しやすく、更新時のアニメーションも付けやすい。日本語フォントも扱える。
- B. wordcloud2.js(Canvas描画): 導入は簡単だが、更新ごとに全体を描き直すため、語が動き回りやすい。
- C. 自前実装: 自由度は高いが、配置アルゴリズムの実装・検証コストが大きい。

## Q4. [プロダクト] 主催者の「ルーム作成・リセット」の認証はどうしますか?

参加者はルームコードだけで参加します。ルームを作る・リセットする主催者の権限を、どう守るかを決めます。

- A. 主催者キー方式(推奨): ルーム作成時に、ルームコードとは別の主催者用キーを発行する。リセット・終了にはそのキーが必要。アカウント登録が不要で、ワークショップ用途に合い、参加者が勝手にリセットすることを防げる。
- B. 共通の管理パスワード: 運営者が決めた1つのパスワードで、ルーム作成・リセットを行う。簡単だが、パスワードの管理・共有が必要。
- C. Amazon Cognito等でログイン: 本格的だが、個人情報(メールアドレス等)を保持することになり「個人情報は保持しない」方針と合わない。
- D. 認証なし(誰でも作成・リセット可): 実装は最小だが、悪用されるとワークショップが止まるため非推奨。
- X. Other (please specify)

[Answer]:A

## Q5. [プロダクト] ルームのデータはいつ削除しますか?

「ワークショップ終了後に削除」の具体的な方法です。

- A. 主催者が「終了」を押すと即削除 + 作成から24時間で自動削除(DynamoDB TTL)(推奨): 押し忘れても残らず、削除の仕組みが追加の運用なしで動く。
- B. 主催者の手動削除のみ: 押し忘れるとデータが残り続ける。
- C. 自動削除のみ(期間は7日など長め): 主催者の操作は不要だが、終了後も一定期間データが残る。

## Q6. [プロダクト] ワードクラウドに出す語の絞り込みはどこまで行いますか?

- A. 既定の除外のみ(推奨): 日本語は助詞・助動詞・記号・数字などを品詞で除外し、英語は一般的なストップワード(the, is, a など)を除外する。大文字小文字は統一して集計する。
- B. 既定の除外 + 主催者がルームごとにNGワードを追加できる: 会場で不適切な語を非表示にできるが、画面と管理機能の実装が増える。
- C. 除外なし(入力された語をそのまま集計): 助詞が大きく表示されてしまうため、ご要件と合わない。
- X. Other (please specify)

- A. ZIPで配布し、各自がデベロッパーモードで読み込む(推奨): Chrome Web Storeの審査・公開が不要で、すぐ使える。ワークショップ冒頭の案内に手順が1つ増える。

## Q8. [アーキテクト] URLのドメインはどうしますか?

- A. AWSの標準ドメインのまま(推奨): CloudFront・API Gatewayが発行するドメインで、HTTPS/WSSは標準で有効。追加費用・DNS設定が不要。CORSなどの許可元もこのドメインに固定できる。
- B. Route 53で独自ドメインを使う: 覚えやすいURLにできるが、ドメイン費用、証明書、DNS設定が増える。
