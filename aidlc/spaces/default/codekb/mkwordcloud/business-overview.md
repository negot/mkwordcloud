# Business Overview

## Purpose
ワークショップ向けのリアルタイム・ワードクラウド。主催者がルームを作成して画面(スライド)に投影し、参加者はルームコードで参加して単語や短文を送る。送信テキストは語に分割・集計され、表示画面へ即時反映される。

## Roles
- **主催者(host)**: ルーム作成、表示画面(viewer)、リセット/終了(ホストキー必須)。
- **参加者(participant)**: Chrome 拡張機能のポップアップ、またはスマートフォン向けの入力フォーム(web の `join.html`、`?room=CODE` で参加)からルームコードで参加し、テキストを送信する。
- **viewer**: 表示画面の WebSocket 役割。

## Key Functionality
- ルーム作成(8 文字コード、24 時間で自動削除)
- テキスト送信(100 文字まで、1 秒間隔・1 分 20 回のレート制限)、語分割と集計、上位 100 語の表示
- 主催者によるリセット/終了
- モバイル入力フォーム(join): 参加、送信、自分の送信履歴の表示(拡張機能と同じ通信契約)
- 承認つきデプロイ(`npm run deploy`、docs/deploy.md)

## 守っている業務上の約束
- 入力テキストそのものは保存もログ出力もしない。残るのは語ごとの出現回数だけ(FR3.7、NFR3.3)。表示画面が受け取るのも語と回数だけで、誰がどの文を送ったかは viewer に出ない。
- データは使い捨て。ルームは 24 時間で消え、終了すると全データを削除する。

## Context for the Active Intent
表示画面に「入力リスト」パネルを足す(上半分にワードクラウド、下半分に送信されたキーワードと文のスクロール一覧)。現在の viewer には語の集計しか届かないため、文を一覧に出すには「入力テキストは保存もログ出力もしない」という約束との関係を決める必要がある。技術的な接点は api-documentation.md(`update` の中身)、architecture.md(データの流れ、文が捨てられる箇所)を参照。
