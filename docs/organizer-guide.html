1. 全体像

役割使うものやること
主催者(管理者)表示ページ(ブラウザ)ルームの作成、プロジェクターへの投影、リセット・終了
参加者Chrome 拡張機能「ワードクラウド送信」ルームコードを入れて参加し、言葉を送る(docs/participant-guide.html を配布)

現在のURL(東京リージョン)

表示ページhttps://d1l71d169uog3u.cloudfront.net
ダッシュボードCloudWatch のダッシュボード wordcloud-workshop(東京リージョン)。npm run deploy の出力 DashboardUrl から開けます
スタックを作り直すと URL が変わります。その場合は、cdk-outputs.json の WebUrl を使い、拡張機能の ZIP も作り直してください(7.)。

動作の目安(AWS 上で確認済み)

  • 100人が3.5秒ごとに送信しても、取りこぼしなし。表示への反映は 95% が 0.13秒以内。
  • データは、ルームの終了時か、作成から24時間で自動削除されます。名前などの個人情報は保存しません。

2. 前日までの準備

  1. 拡張機能の ZIP を用意する。 プロジェクトのフォルダで次を実行し、dist/wordcloud-extension.zip を作ります。 
    npm run apply-outputs
    これで ZIP の接続先が、デプロイ済みのサーバーになります。
  2. 参加者へ配布する。 次の2つを、メールやチャットで事前に送ります。
    • dist/wordcloud-extension.zip
    • docs/participant-guide.html(参加者向け手順書)
    当日に入れてもらうより、事前に入れてもらうほうが、開始が早くなります。
  3. 自分で一度通しで試す。 表示ページでルームを作り、拡張機能で参加して、言葉が表示されることを確認します。試したルームは 終了 で削除します。
会社が管理しているパソコンでは、拡張機能(デベロッパー モード)が使えない参加者がいるかもしれません。事前に確認を呼びかけると安心です。

3. 当日の流れ

開始の15分前

  1. 投影するパソコンで、表示ページ https://d1l71d169uog3u.cloudfront.net を開きます。
  2. ルームを作成 を押します。
  3. 画面にルームコード(8文字)と主催者キーが出ます。
    主催者キーは必ず書き留めてください。 リセットと終了に使います。主催者キーはこのパソコンのブラウザにだけ保存されます。別のパソコンやブラウザでは リセット と 終了 のボタンが出ません。主催者キーは参加者に見せないでください。
  4. 表示を開始 を押すと、ワードクラウドの画面になります。右上に「接続中(リアルタイム)」と出ていれば準備完了です。
  5. サーバーを温める。 自分の拡張機能でこのルームに参加し、日本語の言葉を1回送ります。最初の日本語の送信だけ、辞書の読み込みで約3秒かかるためです。送った言葉が表示されたら リセット で消します。
  6. CloudWatch のダッシュボード wordcloud-workshop を、手元の別の画面で開いておきます(異常の通知は届かない設定のため)。

開始時

  1. ブラウザを全画面表示にして(Mac は Ctrl+⌘+F、Windows は F11)、プロジェクターに映します。
  2. 参加者にルームコードを伝えます(画面右上にも表示されています)。
  3. 拡張機能をまだ入れていない人には、参加者向け手順書の「2」を案内します。

4. 開催中の操作

やりたいこと操作
別のお題に切り替えたい(表示を空にしたい)右上の リセット を押して、確認で OK を押す。集計が0に戻り、参加者はそのまま同じルームで続けられます。
ワークショップを終える右上の 終了 を押して、確認で OK を押す。データはすぐにすべて削除され、元に戻せません。 結果を残したい場合は、先に画面のスクリーンショットを撮ってください。
別のパソコンで表示だけしたい表示ページのホームで、ルームコードを入れて 表示 を押す(この画面ではリセット・終了はできません)。
状態を確認したいダッシュボードの「Lambda エラー数」と「アラームの状態」を見る。エラーが0なら正常です。

参加者の送信の制限

  • 1回100文字まで。1人あたり1秒に1回、1分に20回まで。
  • 日本語は単語に分けられ、助詞などは表示されません。同じ人が1回の送信で同じ言葉を何度書いても、1回として数えます。
  • 不適切な言葉を個別に消す機能はありません。表示されてしまった場合は リセット を使います。

5. 困ったとき

症状対応
表示ページが更新されない・「再接続しています…」が続くブラウザを再読み込みします(⌘+R / F5)。集計はサーバーに残っているので、表示は元に戻ります。
参加者が「ルームが終了したか、存在しません。」と言われるルームコードの打ち間違いが多いです。紛らわしい文字(0とO、1とI)はコードに使っていません。正しいコードを再度伝えます。
参加者が「送信が早すぎます」「上限に達しました」と言われる正常な制限です。少し待ってから送るよう案内します。
全員が送れなくなったダッシュボードでエラーを確認します。解決しなければ、新しいルームを作り、新しいコードを伝えます(参加者はコードを入れ直すだけで参加できます)。
リセット・終了ボタンが出ないルームを作ったパソコン・ブラウザで開いていません。ルームを作ったパソコンで操作するか、新しいルームを作ります。
拡張機能を入れられない参加者がいる会社の管理で制限されている可能性があります。ほかの参加者と一緒に送ってもらうなど、運用で対応します。

解決しない場合は、AWS アカウントの担当者に連絡してください。詳しい手順は aidlc/spaces/default/intents/261120-realtime-wordcloud/operation/deployment-pipeline/rollback-runbook.md にあります。

6. 終了後

  • 必要なら、ワードクラウドの画面のスクリーンショットを撮った
  • 終了 を押して、ルームのデータを削除した(押し忘れても24時間で自動削除されます)
  • 参加者に、拡張機能が不要なら削除してよいと伝えた
しばらく使わない場合も、AWS のリソースは残したままで構いません。使っていない間の費用はほぼかかりません。完全に片付ける場合は 7. の「削除」を行います。

7. デプロイと削除(技術担当者向け)

AWS の認証情報が設定された端末で、プロジェクトのフォルダから実行します。詳しくは README.md を参照してください。

更新をデプロイする

npm install
npm test
npm run deploy
npm run apply-outputs
  • リージョンの既定は東京です。別のリージョンにする場合は WORDCLOUD_REGION を指定します。
  • デプロイに成功したら、Git のタグ deploy-YYYYMMDD-N を付けます。
  • デプロイの直後に、2. の「通しで試す」を行います。

負荷試験(任意)

npm run load-test -- --api <ApiUrl> --ws <WsUrl> --clients 100 --duration 30

すべて削除する

npx cdk destroy --app "npx tsx infra/bin/app.ts"
表示ページ、API、データがすべて削除されます。配布済みの拡張機能も使えなくなります。
